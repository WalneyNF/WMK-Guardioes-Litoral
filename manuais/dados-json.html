Manual de arquivos JSON — v0.3.0

Walney Moreira Klein — walneyk@hotmail.com

1. Como iniciar corretamente

A v0.3 lê os dados por fetch() e não funciona aberta diretamente em file://. Abra um terminal na pasta do projeto e execute:

py -m http.server 8000

Depois visite http://localhost:8000/. É necessária conexão com a internet para carregar Three.js do CDN. Para edição local, use o VS Code ou qualquer editor JSON.

2. Arquivos

dados/mapas.json: lista de mapas; dados/profissoes.json: lista de funções profissionais, velocidade, cores, posição inicial e controle de veículo; dados/missoes.json: objeto com uma lista de missões para cada ID de profissão.

Os IDs de profissão devem corresponder às chaves do JSON de missões.

3. Exemplo de mapa

{
  "id": "sol",
  "name": "Praia do Sol",
  "region": "Costa Dourada",
  "icon": "☀️",
  "description": "Calçadão e mar aberto.",
  "sky": "#a6dff0",
  "fog": "#b5d9df",
  "sand": "#e8cb8d",
  "water": "#1685a4",
  "shallow": "#52c9c7",
  "offset": {"x": 0, "z": 0}
}

Esta estrutura é uma entrada dentro de uma lista JSON. Os mapas compartilham a geometria-base da versão atual; alterar campos visuais não cria novos objetos 3D.

4. Exemplo de profissão

{
  "id": "eco",
  "name": "Fiscal ambiental",
  "icon": "🌱",
  "short": "Proteção da fauna.",
  "code": "MEIO AMBIENTE",
  "accent": "#79d68d",
  "shirt": "#3e9b68",
  "pants": "#385843",
  "cap": "#34734e",
  "speed": 7.2,
  "vehicle": false,
  "spawn": [-16, -8]
}

As coordenadas de spawn indicam a posição inicial na cena em unidades do mundo. A opção vehicle distingue, no protótipo, os modelos e movimentos implementados.

5. Exemplo de missão

{
  "eco": [
    {
      "title": "Inspeção ambiental",
      "description": "Verifique a praia e registre a situação.",
      "steps": [
        {
          "type": "inspect",
          "title": "Inspecionar área",
          "detail": "Vá ao ponto sinalizado.",
          "action": "Inspecionar",
          "x": -7,
          "z": -15,
          "reward": 100
        }
      ]
    }
  ]
}

Este exemplo representa apenas a entrada eco; o arquivo completo precisa manter as demais profissões. Para resgates com prazo, utilize "callSeconds": 60 na etapa do tipo rescue.

6. Validação e limitações

O carregador valida IDs, duplicidade, cores hexadecimais, campos de texto, velocidade, coordenadas, limites de quantidade e missões de todas as profissões. Se algum arquivo estiver inválido, o menu exibirá o erro e bloqueará a inicialização.

A versão ainda não dispõe de editor visual JSON, validação semântica completa dos tipos de etapas, IA autônoma nem importação de GLB. Faça uma cópia dos arquivos antes de editar.

7. Exportação e importação

No menu principal, use Exportar dados JSON para obter um pacote versionado contendo os três conjuntos. Edite os dados respeitando o formato e depois use Importar pacote JSON. A validação é feita antes de aplicar; o pacote vale só para a sessão atual. Para tornar as alterações permanentes, atualize os arquivos em dados/.

A última seleção de praia e profissão fica salva no navegador, mas as missões e as posições não são persistidas.

8. Testes

node tests/validar.js

Testa sintaxe e integridade básica do conteúdo. Execute também uma rodada manual no navegador: inicie missão, alterne agentes, conclua etapas, pause, retorne e reinicie.
